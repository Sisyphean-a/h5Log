# H5 Log

测试环境的 H5 远程日志工具。手机上传日志，电脑按客户端查看；多个查看者互不影响。

## 启动

需要 Node.js 24.15+（24 LTS）和 npm。

```sh
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:3000`，首次打开会显示访问蒙版，输入 4 位密钥后进入。密钥在构建时读取 `VITE_ACCESS_KEY`（本地开发可写在 `.env.local`，不会提交到 Git；未设置时使用公开默认值 `2468`，对外部署前务必改成自己的密钥），修改后需重启开发服务或重新构建。解锁状态保存在当前浏览器，清除站点数据后需重新输入。进入后在顶部单行工具栏选择设备、搜索和筛选日志；右侧图标提供跟随、翻页、清空视图及服务状态，悬停可查看操作提示。演示页位于 `http://127.0.0.1:3000/demo.html`，可发送 console、异常及接口日志，在工作台查看真实 SDK 上传的数据。

构建部署后的工作台支持通过路径预设来源和搜索条件（只在打开页面时初始化）：

- `/console/埋点`：控制台，搜索“埋点”。
- `/interface`：接口，搜索条件为空。
- `/error/超时`：异常，搜索“超时”。

路径相对于工作台地址；例如部署在 `/h5-log/` 时使用 `/h5-log/console/埋点`。第二段为可选关键词，包含 `/` 等特殊字符时须进行 URL 编码。设备、级别等其他条件不由路径设置，访问门禁仍然生效。

开发：

```sh
npm run dev
```

工作台在 `http://127.0.0.1:5388`，日志服务在 `http://127.0.0.1:3000`。服务端和页面支持热更新；修改 SDK 后重新运行开发命令以构建 SDK。

只改前端、同时保留正在运行的日志服务：

```sh
npm run dev:web
```

Vite 在 `5388` 提供工作台热更新，`/api` 默认代理到本地服务的 `3000`。若使用默认 Compose 容器，可在启动开发命令前设置 `H5_LOG_DEV_PROXY=http://127.0.0.1:3685`；不会清空容器里的日志。

## 两个包

| 包                             | 职责                                                       |
| ------------------------------ | ---------------------------------------------------------- |
| `packages/sdk` · `@h5-log/sdk` | console、JS 异常采集、独立上传、Axios 与可选 fetch 接入     |
| `packages/app` · `@h5-log/app` | 日志服务（接收、内存保留、查询、SSE）与工作台页面，构建为同一个产物 |

`packages/app` 内部 `src/server` 是 Node.js 日志服务，`src/web` 是 Vue 3 + Naive UI 的工作台（Vite 构建，组件库按需引入）。构建输出 `dist/server/cli.mjs`（自包含单文件，只依赖 Node 内置模块）与 `dist/web`，服务进程直接托管 `dist/web`；部署时只需 `dist` 目录，不需要 `node_modules`。

SDK 是独立分发的浏览器 ESM 包，保持单独打包，不随服务一起部署。

只需要部署一个 Node.js 服务，页面随服务一起提供。运行时不需要数据库、WebSocket 或 `node_modules`；可使用 Docker Compose，或直接复制构建后的 `packages/app/dist` 到服务器运行，详见[部署](#部署)。

## 接入 SDK 与排查停止上报

Android 原生应用通过 HTTP 上报，见 [Android 原生 Kotlin 接入指南](docs/kotlin-android.md)。WebView 网页仍按 H5 项目接入。

SDK 接入步骤见 [SDK 说明](packages/sdk/README.md)。接入其他 H5 项目时先打包：

```sh
npm run pack:sdk
```

在目标项目安装生成的 `h5-log-sdk-0.1.1.tgz`，无需先发布 npm。该包是 ESM，适合现有 Vite 项目。

手机停止上报时，按 [SDK 本地诊断完整步骤](packages/sdk/README.md#本地诊断不依赖上传) 完成：更新实际安装的 SDK → 在现有初始化处挂接测试只读入口 → 发布并确认手机加载新构建 → 故障时手动读取两份快照。**仅更新 SDK 不会自动生成 `window.__H5_LOG_STATUS__`。** 文档同时说明入口缺失、旧版本、退避及 `Failed to fetch` 的判断；不要把 vConsole 仍有本地输出或历史 HTTP 202 当作当前上传成功。

## 日志规则

- 工作台首次打开显示毛玻璃访问蒙版；密钥在构建时由 `VITE_ACCESS_KEY` 注入，未配置时使用公开默认值 `2468`（4 位数字或字母，大小写不敏感）。真实密钥放 `.env.local` 或 Compose 的 `.env`，不进 Git；修改后需重新构建。解锁状态存在当前浏览器的 IndexedDB，清除站点数据后需重新输入。密钥仍会打进前端 JS，是纯前端弱门禁，日志接口本身不校验；需要真正隔离时应在反向代理加认证。
- 仅在 H5 显式启用 SDK 时采集，生产构建应保持关闭。
- 测试数据原样采集，不脱敏。普通日志（包括桥接输出）统一由 console 自动采集，无需单独接入或分类；SDK 保留调用时快照，无法恢复业务代码已经摘要或截断的内容。
- 服务端按**接收时间**保留最近 12 小时；服务器重启后日志清空。
- 默认最多保留 8,000 条、16 MiB 的日志序列化数据，先达到哪个限制就先淘汰最旧记录。这不是 Node.js 进程总内存限制，也不保证完整存满 12 小时。需要更大窗口时调高 `MAX_LOGS`/`MAX_MEMORY_MB`。
- “客户端”是应用、环境和 deviceId 的组合。测试宿主可显式传入 URL 的 googleGaid 固定设备身份，未传时沿用浏览器本地标识；页面每次初始化仍产生新会话。设备名称使用型号，同型号的不同设备添加 -1、-2、-3，同一设备跨应用复用编号。
- 页面显示“最近上报”，不将没有产生新日志误报为设备离线。服务状态面板分别显示电脑实时连接、最近收到推送和所选设备最近上报时间，电脑连接正常不代表手机仍在上报。
- 工作台默认聚焦一个设备：打开时自动选中最近上报的客户端，顶部工具栏保留切换入口；不用先筛应用/环境就能看日志。实时正文按应用、环境和设备范围订阅，目录仍全局可见；关键词、级别与来源只影响阅读，不缩减该设备的本地存档范围。未订阅设备的正文不会持续下载或存入本地历史。
- 每页 200 条，可翻阅更早的保留日志；会话列表覆盖当前客户端范围内所有保留会话。暂停自动滚动仍接收日志；跟随依据最新可见事件而非列表条数触发，达到 200 条上限后仍自动到底，重新开启跟随立即到底，本地历史模式不自动滚动；「清空视图」只清空当前浏览器的当前列表，不删除服务器日志、设备列表或本地历史；「隐藏其他设备」只过滤当前浏览器的设备下拉，设备重新上报后会再次出现。
- 搜索在顶部输入框完成，忽略大小写：`a && b` 同时包含，`a || b` 任一包含，`-c` 排除；`&&` 优先于 `||`，例如 `订单 && -失败 || 超时` 表示“包含订单但不含失败，或者包含超时”。普通文本仍按整串子串匹配（空格不拆词），不支持括号、正则或字段语法。输入时先立即预览当前页，250 毫秒防抖后再向服务端查询；实时日志与本地历史沿用同一规则，只高亮正向关键词。
- 列表对日志前缀标签、URL、请求方法、错误关键词、耗时单位、请求路径和源码位置做轻量高亮；搜索命中在原文上加底色，不改变筛选结果。
- 工作台把收到的日志旁路写入浏览器 IndexedDB（默认 50,000 条 / 64 MiB，可回看服务端保留窗口之外的记录）；本地历史只属于当前浏览器，不跨设备同步；重复收到日志不重复计容量，多开页面共享事务计数。服务器重启（serverId 变化）后重置，并隔离未落盘的旧批次。旧版本错误计数会在原数据库中校准一次，不升级数据库版本或清除有效当前实例日志、宽度偏好；已经丢失的历史无法恢复。清空视图不清本地历史，存储不可用时自动退回服务端窗口。
- 选中网络日志可在详情中查看同一次请求与响应；当前页内可见的关联记录会在列表旁用细折线连接。仅当两条记录仍在服务器内存中时才能关联，已淘汰的记录会提示无法关联；详情仍可复制原始 JSON。桌面可拖动列表与详情之间的分隔条调整宽度，也可聚焦分隔条后用左右方向键微调；宽度自动保存到浏览器 IndexedDB，下次打开同一站点时恢复，不随日志清空或服务重启重置；窄屏保持全屏详情。
- SDK 队列最多 1,000 条、4 MiB；默认每 500 毫秒最多发送一批 50 条（`flushIntervalMs` 可调，最小 50），失败按 1–30 秒退避，网络或页面恢复后立即尝试。业务流程不等待上传，但快照与序列化仍有同步开销，不能保证宿主零卡顿；详见 [SDK 的宿主开销与传输](packages/sdk/README.md#宿主开销与传输)。`getStatus()` 可检查采集进度、定时器心跳、在途阶段和最近失败，读取不依赖上传；见 [SDK 本地诊断](packages/sdk/README.md#本地诊断不依赖上传)。
- 服务端每 15 秒发送目录心跳，电脑连续 45 秒收不到事件会主动重建 SSE 并补读当前页；重新联网或恢复前台也会重连。列表、详情和状态请求连同响应正文限时 10 秒，失败显式反馈，补读失败仍保留缓冲内的实时增量。
- 接入只需初始化 console/全局异常采集，再按实际请求方式挂载 Axios 默认 adapter 或显式开启 fetch 采集；二进制、事件流与请求流不读取正文，`Request` 自带流不会被克隆。接口收发通过 `requestId` 对应。
- 单条日志上限 128 KiB。快照最多展开 12 层、处理 2,000 个值、保留合计 64K 字符的字符串；触发限制会留下可见标记。文件只记录名称、类型、大小，不上传二进制内容。
- 页面退出、WebView 被系统终止、服务器不可达时允许丢失日志，不提供可靠消息队列或持久化补发。

## 部署

### Docker Compose

服务器需要 Docker、Docker Compose、运行中的 Docker 守护进程和同机 Nginx，不需要安装 Node.js。以下以 `/data/www/h5-log` 为项目目录；执行 Docker 命令的账号需要 Docker 权限。首次构建需要访问 Docker 镜像仓库和 npm。已有项目目录时跳过克隆，进入已有目录即可。

```sh
cd /data/www
git clone <仓库地址> h5-log
cd /data/www/h5-log
```

先确认宿主机 `3685` 端口空闲（例如执行 `ss -lnt | grep ':3685'`），并确认不存在其他用途的同名 `h5-log` 容器。若端口冲突，修改 `compose.yaml` 的宿主机端口，并同步修改下面的 Nginx 代理端口；不要直接删除已有容器。

设置自己的访问密钥（不设置则使用公开默认值 `2468`；对外部署前务必修改）：

```sh
cp .env.example .env
# 编辑 .env，把 VITE_ACCESS_KEY 改成自己的 4 位密钥
```

`.env` 已被 Git 忽略，Compose 会把它作为构建参数传给页面；修改后需要重新构建镜像。

构建并启动：

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 h5-log
curl http://127.0.0.1:3685/api/health
```

镜像是 `h5-log:latest`，容器名为 `h5-log`；默认只将宿主机 `127.0.0.1:3685` 映射到容器 `3000`，不直接对外开放端口。镜像内以非 root 用户运行，健康检查访问容器内的 `PORT`。容器使用 `unless-stopped` 重启策略，Docker 重启后未被手动停止的容器会自动启动。

配置下方的 Nginx 代理后，访问 `https://<站点域名>/h5-log/`；检查配置并重载：

```sh
sudo nginx -t
sudo systemctl reload nginx
```

只有配置检查通过才重载；HTTPS 可能由另一层代理或负载均衡提供，需确认请求会进入添加配置的 `server`。

日常管理命令在项目目录执行：

```sh
cd /data/www/h5-log
docker compose ps                     # 查看状态
docker compose logs -f h5-log         # 查看日志，Ctrl+C 退出
docker compose restart h5-log         # 重启
docker compose stop                   # 停止
docker compose start                  # 启动已停止的容器
```

更新已通过 Git 克隆的项目：确认当前分支和本地改动，再拉取目标版本并重新构建：

```sh
cd /data/www/h5-log
git status
git pull --ff-only
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:3685/api/health
```

如果源码通过其他方式上传，先更新完整源码，再执行 `docker compose up -d --build`。重启或重建会清空服务端内存中的日志；更新时也会短暂中断服务。失败时用 `docker compose logs --tail=100 h5-log` 查看，不要将依赖安装警告直接当作部署成功或失败的证据。

### 直接运行 Node.js

完成 `npm ci && npm run build` 后运行 `npm start`。默认监听 `127.0.0.1:3000`，适合由同机 Nginx 提供 HTTPS 入口。

页面密钥在构建时读取 `VITE_ACCESS_KEY`：可在仓库根 `.env.local` 写入（Vite 自动加载，且不会提交），或构建时临时指定 `VITE_ACCESS_KEY=abcd npm run build`。它不属于服务端运行环境变量，改密钥后必须重新构建页面。

无 Docker 时只需把 `packages/app/dist` 拷到服务器，用 `node dist/server/cli.mjs` 启动（需要 Node.js 24.15+）。`dist` 包含自包含的服务进程和页面资产，不含第三方依赖。

可设置环境变量：

| 变量               | 默认值      | 含义                                   |
| ------------------ | ----------- | -------------------------------------- |
| `HOST`             | `127.0.0.1` | 监听地址，局域网直连可改为 `0.0.0.0`   |
| `PORT`             | `3000`      | 监听端口                               |
| `MAX_LOGS`         | `8000`      | 内存日志条数上限                       |
| `MAX_MEMORY_MB`    | `16`        | 内存日志序列化数据大小上限             |
| `RETENTION_HOURS`  | `12`        | 保留时长（小时，可降到 1–2 省内存）    |
| `ALLOWED_ORIGINS`  | `*`         | 允许上传的页面来源；多个来源用逗号分隔 |

此前未启用传输压缩的本机样本中，默认配置下进程稳定在约 45–55 MiB，突刺上传峰值约 80–100 MiB 后回落；压缩会增加缓冲与 CPU 开销，这些样本不是当前部署的内存保证。Docker 镜像默认带 `--max-old-space-size=128 --max-semi-space-size=16`（实测峰值约 83 MiB）。调大 `MAX_MEMORY_MB` 时要同步放宽该上限，否则会 OOM。

### Nginx 与 SDK 地址

在目标站点已有的 Nginx `server` 中新增以下配置，不需要修改站点的其他路径。示例使用 Compose 的默认端口，直接运行 Node.js 时将代理端口改为 `3000`：

```nginx
location = /h5-log {
    return 301 /h5-log/;
}

location ^~ /h5-log/ {
    proxy_pass http://127.0.0.1:3685/;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Connection "";
    proxy_buffering off;
    proxy_read_timeout 60s;
    client_max_body_size 1m;
}
```

`proxy_pass` 末尾的 `/` 用于去掉 `/h5-log/` 前缀。检查并重载 Nginx 后，从站点的 `/h5-log/` 访问工作台；SDK 的 `endpoint` 填写该站点的完整 HTTPS 地址，路径为 `/h5-log/api/logs`。工作台不绑定域名，也支持部署在其他由代理去除前缀的子路径或根路径；子路径必须以 `/` 结尾。HTTPS 的 H5 应配置 HTTPS 日志地址。

服务端按浏览器能力压缩较大的 JSON 查询响应与 SSE；SSE 每次写入同步刷新压缩流，代理仍须关闭缓冲。手机大批次使用 gzip 时，代理应透传 `Content-Encoding`，跨域预检允许该头；服务端对压缩前后的上传都保留 1 MiB 上限。升级时先更新服务端，再更新宿主项目安装的 SDK 并重新构建 H5，已有工作台页面也应刷新。仅更新服务端不能替换已经运行在手机里的 SDK。

服务面向受控测试环境，未内置账号和权限系统；需要入口认证时由反向代理承担，`ALLOWED_ORIGINS` 只限制浏览器跨域来源，不是认证机制。日志保存在内存，重启或重建容器会清空。
