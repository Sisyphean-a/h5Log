# 远程日志

scope: context:remote-logging
packages: sdk, app

## 规范词

- **日志事件**：一次 console 输出、JS 异常、接口请求/响应或显式业务记录。请求和响应分开记录，以 requestId 关联。
- **应用**：接入 SDK 的 H5 包身份 appId；26 是首个预期接入包，不是 SDK 的内置业务。
- **客户端**：appId、环境和 deviceId 的组合。SDK 支持宿主显式传入稳定 deviceId，当前测试宿主使用 URL 的 googleGaid；未传时沿用浏览器本地标识。它不以业务用户号识别；工作台用“设备”作为它的界面称呼。
- **页面会话**：一次采集器初始化对应的 sessionId；与业务登录会话无关，页面重建产生新会话。
- **查看者**：打开工作台的一个浏览器连接；多个查看者读取相同日志，筛选与清空彼此独立。

## 已确认规则

- 用户确认当前全部为无真实价值的测试数据，原样采集，不脱敏。
- 设备身份与名称分开：相同 GAID 的页面重建、浏览器存储清除不新增同应用同环境的设备选项；名称只传型号，同型号的不同 deviceId 在工作台目录添加 -1、-2、-3，同一设备跨应用和环境复用编号。编号基于当前保留目录的首次出现顺序，不随最近上报排序变化；服务重启或目录淘汰不保证保留旧编号。
- 工作台按设备连续查看各次采集，不提供页面会话筛选，也不在常规详情中展示会话标识；底层 sessionId 继续用于分组、去重和请求关联，原始复制数据不变。
- 接入只有普通日志与接口两部分，全局 JS 异常默认自动采集。桥接及其他业务输出都是普通 console 日志，不设独立来源、筛选或接入步骤；接口请求参数与响应正文在业务解包前保留。
- 接口自动采集覆盖 Axios 默认 adapter，并可显式启用 fetch 采集；不承诺覆盖所有网络通道。Fetch 的文本/JSON 响应在独立克隆流中有限读取，不阻塞原响应；二进制、事件流与请求流不读取正文。
- 服务端日志按服务器接收时间最多保留 12 小时，容量先满时淘汰旧记录，淘汰槽即时解除正文引用。服务重启可清空，无需持久化、跨重启恢复或严格可靠投递。
- 本地历史是当前浏览器看过的日志缓存，独立于服务端保留窗口，按自身容量淘汰，不承诺可靠存储。服务端清理不清空正在看的本地历史页；列表滚动不自动切换分页，“更早”与“最新”由用户手动切换，无更早记录时保留当前页。
- 工作台以服务端日志页作为计数基线，对其后的新 SSE 日志按递增 id 去重，避免快照与推送交错时重复计算会话。会话索引刷新与新日志并发时用 revision 校验并重读，避免旧索引覆盖新事件。
- 日志上传不作为业务成功的前置条件。连接、序列化或服务故障不改变业务请求结果；资源限制以可见标记或采集状态反映。
- SDK 仅在显式开启时运行；生产保持禁用。工作台根据可见上报记录提示“开始上报／重新开始上报”，不据此宣称真实启动时刻，也不把静默等同离线或伪造断开；工作台到日志服务的连接状态不代表设备在线状态。
- 以最小可用和后续按需扩展为准，不预建复杂认证、设备管理、请求瀑布图、分析大屏或数据库系统。

代码锚点：packages/sdk/src/types.ts、index.ts、axios.ts；packages/app/src/server/store.ts；packages/app/src/web/main.ts。
